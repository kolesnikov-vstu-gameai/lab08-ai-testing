## Пример выполнения

**Где это в играх.** King использовала ботов, обученных на ходах реальных игроков, чтобы ещё до релиза оценить
сложность новых уровней Candy Crush. EA SEED исследовала агентов, которые сами бегают по картам Battlefield
и ищут места, где можно застрять или провалиться сквозь геометрию. Процедурным играм нужна автоматическая проверка,
что каждый сгенерированный уровень проходим.

**Зачем:** ИИ ломается не на «счастливом пути», а на редких комбинациях, которые тестировщик вручную не повторит.
Unit-тесты FSM, бот-плеер, тест на 100 seeds и CI в этой ЛР — тот же подход в миниатюре.

**Пример unit-теста** на FSM из ЛР 1 (`tests/unit/`):

```python
def test_full_chase_cycle():
    g = GuardFSM()
    for trigger in ["see_player", "confirm", "in_range", "out_of_range", "lost"]:
        assert g.fire(trigger), f"переход по {trigger} из {g.state} не сработал"
    assert g.state == State.RETURN   # если в ЛР 1 добавили Search, здесь будет State.SEARCH
    assert len(g.history) == 5
```

Хорошие кандидаты для остальных тестов: граница угла обзора (59° виден, 61° нет), препятствие между стражем и игроком,
Search → Patrol по таймауту, приоритет правил из ЛР 3, детерминизм генератора из ЛР 7.

## Как сдавать

1. Работайте в этом репозитории, коммитьте по шагам (`step-1`, `step-2` …) — история коммитов учитывается.
2. Отчёт пишите в `docs/report.md` (черновик по разделам, 4–6 стр.), затем перенесите в официальный шаблон отчёта, принятый на кафедре, и экспортируйте в PDF (`docs/report.pdf`).
3. Видео — на YouTube/Диск, ссылку в README и в отчёт. Файлы видео в git не кладём.
4. Готовую работу отметьте тегом `git tag v1.0 && git push --tags` и создайте Release.
